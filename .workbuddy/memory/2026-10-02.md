# 2026-10-02

## 修复 GitHub Actions macOS 安装包构建失败

### 现象
- 唯一一次 Release run（run 36698584531，tag v1.0.0，2026-09-30T09:49Z）中
  Windows 成功、macOS 失败；失败步骤是 `打包 dmg（arm64 + x64）`，耗时 56s。
- 关键日志：
  ```
  • building target=DMG arch=arm64 file=release/imagekit-upload-1.0.0-arm64.dmg
  • building target=DMG arch=x64  file=release/imagekit-upload-1.0.0-x64.dmg   ← 两架构并发
  ⨯ unable to execute hdiutil args=["detach","-quiet","/Volumes/ImageKit Uploader"]
      error=Exit code: 16.  Above command failed, retrying 5 more times   （6 次全失败）
  ⨯ Exit code: 1. Command failed: hdiutil detach -quiet /Volumes/ImageKit Uploader
  ```
- 根因：dmg 挂载卷名取自 `dmg.title`（= productName "ImageKit Uploader"），
  **两个架构卷名相同**，而 electron-builder 默认**并行**处理两个 arch，
  卷互相占用导致 `hdiutil detach` 一直 "Resource busy"(exit 16)；
  runner 上的 Spotlight 索引会加剧占用。本地因时序/环境不同侥幸通过。

### 修复（3 个文件）
1. `electron-builder.yml`：`mac.target` 去掉写死的 `arch: [arm64, x64]`。
   —— 实验证明 **config 里写死 arch 会覆盖命令行 `--arm64/--x64`**，
   不删掉就无法把两个架构拆开。
2. `package.json`：`build:mac` / `build:all` 改为串行两次调用
   `electron-builder --mac --arm64 && electron-builder --mac --x64`。
3. `.github/workflows/release.yml`：新增 `sudo mdutil -a -i off`（关 Spotlight 索引），
   打包步骤改为 `build_dmg()` 函数串行执行两个架构，失败时清理残留卷后重试一次。

### 关键经验
- **没有 `gh` CLI 也能拿到 Actions 失败日志**：本机钥匙串里有 github.com 凭据
  （`security find-internet-password -s github.com -w`），
  `curl -L -H "Authorization: token $CRED" .../actions/jobs/<job_id>/logs`
  返回的是**纯文本流而非 zip**，需按 `^时间戳Z` 切行、去掉 `\r` 和 ANSI 转义。
  job 列表/步骤耗时可从 `/actions/runs/<id>/jobs` 拿到（含每步 started_at/completed_at）。
- `annotations` 接口（公开）只有 "Process completed with exit code 1."，没有真实报错。
- 本机验证 electron-builder 受 WorkBuddy 沙箱限制：
  写 /tmp 会被 "Brokered file token refused" 拦、删除 `release/mac-arm64/**`
  会被 Security Center 拦；`npm ci` 也无法在沙箱内完成（file-delete 被拒）。
  本地复现不可靠，最终以 CI 日志 + 单架构选择行为为依据。
