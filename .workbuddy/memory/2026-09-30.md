# 2026-09-30

## ImageKit 桌面上传工具（首版完成）

**目标**：imagekit.io 上传工具，支持 macOS / Windows，React + Vite + TypeScript，
Public Key / Private Key / Name 写在配置文件里由后期配置。

**技术选型与结论**
- 因为要让用户本地保存 Private Key，做成 **Electron 桌面应用**（纯 Web 页面无法安全持有私钥）。
- 脚手架用 `electron-vite`（main / preload / renderer 三端统一构建）+ `electron-builder`（mac dmg / win nsis）。
- 签名与上传**全部放在主进程**：`HMAC-SHA1(privateKey, token + expire)`，渲染进程经 contextBridge 白名单 IPC 拿结果，私钥不进网页上下文。
- 上传用 `https.request` 手工拼 multipart，好处是可以做**真实字节级进度**（fetch+FormData 拿不到进度）。分片 128KB，进度事件 80ms 节流。
- 缩略图用 Electron 内置 `nativeImage` 降到 96px 再转 dataURL，避免为大图做 base64 常驻内存。
- 拖拽取路径用 preload 里的 `webUtils.getPathForFile(file)`（Electron 32+ 已移除 `File.path`）。
- 剪贴板截图没有本地路径，走 `files:saveTemp` 落盘到 temp 目录再上传。

**配置文件位置**：`app.getPath('userData')/config.json`
- macOS `~/Library/Application Support/ImageKit Uploader/config.json`
- 支持环境变量 `IMAGEKIT_UPLOAD_CONFIG` 覆盖路径
- 首次启动自动生成带 `_comment` 注释键的模板；读取时忽略下划线开头的键，保存时保留注释头

**踩坑记录（重要，下次别再踩）**
1. 本机 `~/.npm/_cacache` 里有 root 属主文件，且沙箱会拦截 npm 的批量删除
   → 用项目内缓存：`npm install --cache ./.npm-cache`，且需要提权执行。
2. 本环境预设了 `ELECTRON_RUN_AS_NODE=1`（WorkBuddy 自身是 Electron 应用），
   直接 `electron .` 会以纯 Node 启动并报
   `Cannot read properties of undefined (reading 'requestSingleInstanceLock')`。
   **验证启动必须用 `env -u ELECTRON_RUN_AS_NODE ./node_modules/.bin/electron .`**。
3. `screencapture` 在本机没有屏幕录制权限，截图验证不可用，只能靠进程存活 + 日志判断。
4. electron-vite 加载 TS 配置时会残留 `electron.vite.config.*.mjs`，已加入 .gitignore 并清理。

**验证结果**：`npm run typecheck` 通过、`npm run build` 三端产物正常、启动冒烟测试进程存活无报错。

## 追加：GitHub Actions 构建工作流

新增 `.github/workflows/`：
- `ci.yml` — push main/master + PR + 手动触发；ubuntu 上跑 typecheck + build，**不打安装包**。
  安装步骤设 `ELECTRON_SKIP_BINARY_DOWNLOAD=1` 省掉 ~100MB 的 Electron 二进制下载。
- `release.yml` — push `v*` 标签 / 手动触发；`macos-14` 出 dmg（arm64+x64），`windows-latest` 出 nsis exe；
  tag 触发时用 `softprops/action-gh-release@v2` 自动发 Release，手动触发只产出 artifacts。

关键设计点：
- **依赖源**：仓库 `.npmrc` 指向 npmmirror（本地开发用），CI 里用 `NPM_CONFIG_REGISTRY` 环境变量覆盖回官方源，
  env 优先级高于项目 .npmrc，所以不用改仓库文件。这个模式以后移植到别的项目也适用。
- **版本号同步**：`npm version "${GITHUB_REF_NAME#v}" --no-git-tag-version --allow-same-version`，
  让 tag 版本覆盖 package.json，保证产物文件名和 tag 一致。
- **未签名发布**：`CSC_IDENTITY_AUTO_DISCOVERY: 'false'` 避免 CI 卡在签名身份发现上。
- `electron-builder.yml` 的 artifactName 从 `${productName}` 改成 `${name}`，
  避免产物文件名里带空格（`ImageKit Uploader-1.0.0-arm64.dmg` → `imagekit-upload-1.0.0-arm64.dmg`）。

**本地实跑验证**：`npx electron-builder --mac --publish never` 成功产出两个 dmg
（`imagekit-upload-1.0.0-arm64.dmg` 94MB / `-x64.dmg` 98MB），asar 里只有 `out/` + `package.json`（310K），
打包后的 `.app` 能正常启动。踩坑：electron-builder 会把 Electron 压缩包下到 `~/Library/Caches/electron/`，
沙箱会拦截，必须提权执行；另外我传了 `--arm64` 但它按配置里的 arch 列表把 x64 也打了。

**新增文件**：`.github/workflows/ci.yml`、`.github/workflows/release.yml`、`build/README.md`（说明图标放置位置）。

## 追加：云端目录「单击即选中为上传目录」

**需求**：在「云端目录」里选中某个目录时，上传目录就该是该目录。

**改动**
- `src/renderer/src/components/RemoteBrowser.tsx`：`FolderRow` 交互改成文件管理器习惯——
  **单击目录行 = 设为上传目标**（行高亮 + 「上传目标」标记），**双击 / 点右侧 `→` = 进入目录**；
  删掉原来每行的「设为上传目录」按钮（已冗余）。子目录组头加提示「单击选中为上传目录 · 双击进入」。
- 目标目录比较统一用 `normalizeRemotePath()`（`/a/`、`/a`、`a` 视为同一目录），
  行高亮、顶部 chip、底部按钮三处判断都走它。
- `App.tsx` 的 `handleSelectRemoteTarget`：与当前 `options.folder` 相同则直接 return，
  这样双击时不会被弹两次 toast（`onClick` 会先触发两次）。
- `styles/index.css`：新增 `.r-entry--target` 高亮（accent 底 + 边框 + 加粗名字）。
- 顺手修 bug：`RemoteBrowser.tsx` 里 `FileThumb` 用了 `RemoteFile` 类型但没 import（上一轮加缩略图降级时漏的，
  当时没复跑 typecheck）。

**踩坑（Electron GUI 验证，很值得复用）**
1. **单实例锁会骗人**：`app.requestSingleInstanceLock()` + 残留的
   `~/Library/Application Support/ImageKit Uploader/SingletonLock|Socket|Cookie`
   会让新实例直接 `app.quit()`，于是 `screencapture` 抓到的其实是**旧实例/别人的窗口**——
   我因此一度以为改动没生效。清理：`rm -f "$D"/Singleton*` 再启动。
2. 本机 `ps` / `pkill` 被系统限制（`operation not permitted` / pkill 永远 exit 1），**无法枚举进程**。
   → 用 `kill -0 <pid>` 判断已知 pid；自己的实例用 `$!` 记下来后按 pid kill。
3. **最可靠的窗口验证方式**：主进程里临时
   `BrowserWindow.getAllWindows()[0].webContents.capturePage()` 存成 PNG。
   拿到的是**自己窗口**的内容，不受 z-order / 多实例干扰，尺寸还能反推窗口大小
   （1160x800 的窗口 → 截图 2320x1600 @2x）。比桌面截图靠谱得多，验证完记得还原。
4. 判断「抓到的到底是不是新构建」的土办法：拿源码里新增的**可见文案**当指纹（本次是那行提示语）。
5. 修正此前记录：`screencapture` 其实**可用**（第 29 行「没有屏幕录制权限」的结论已作废）。

## 追加：界面语言切换（默认英文）+ 双语 README

**需求**：加语言切换，默认英文，支持中英，切换后记住；README 出中英两份，默认英文。

**实现（架构）**
- `src/shared/i18n.ts`（新）：唯一文案字典。`en` 用 `as const`，`MessageKey = keyof typeof en`，
  `zh` 声明为 `Record<MessageKey, string>` → **漏翻/键名错在 typecheck 阶段就报错**。
  提供 `translate()` / `createTranslator()` / `normalizeLanguage()` / `localeOf()` / `isCanceledMessage()`。
- `AppConfig` 新增 `language: 'en' | 'zh'`，默认 `en`（同步改了 types → config.ts DEFAULT_CONFIG/normalize →
  config.example.json → 用户的 config.json → README 字段表）。
- `src/main/lang.ts`（新）：主进程语言持有者 `mainT()` / `mainLocale()`；
  在 `config.ts` 的 `normalize()` 末尾 `setMainLanguage(merged.language)`，
  读/存配置都经过它；**兜底分支（读失败/首次生成）也要调**，否则会停留在默认语言。
- `src/renderer/src/lib/i18n.tsx`（新）：`I18nProvider` + `useT()`/`useI18n()`。
- 语言是「即时生效项」（同 theme）：切换即写盘，不等保存。入口两处：顶栏 `.lang-btn` 胶囊（一键切另一种）、
  设置面板顶部新增 INTERFACE 分组里的 `.segmented` 分段控件。

**踩坑（很值得复用）**
1. **App 坐在 Provider 之上**：App 内部不能 `useT()`（要用 `useMemo(createTranslator(lang))`）；
   更隐蔽的是 App 里调用的 `useRemoteBrowser()` 内部 `useI18n()` 只会拿到 context 默认值，
   语言切换对它无效 → 改为接受可选 `{ t, locale }` 覆盖（`options.t ?? ctx.t`）。
2. **禁止硬编码翻译字符串做判断**：原来取消上传靠 `res.error.includes('已取消')`，
   主进程改英文后直接失效 → 新增 `isCanceledMessage()` 对所有语言文案做匹配。
3. **`capturePage()` 会返回上一帧**：语言切换后截图竟然还是英文，一度以为状态回退；
   用 `executeJavaScript` 读 DOM 文本才确认真相。**判断状态用 DOM 断言，截图只做展示。**
4. `mainT()` 必须在函数体内调用，模块顶层 `const X = mainT(...)` 会固化启动语言。
5. `formatRelativeTime` / `remoteBreadcrumbs` 改为接收 `t` / root 名称参数，避免 `lib/utils.ts` 依赖 React context。
6. 排序 `localeCompare(x, 'zh-CN')` → 按当前语言取 locale。

**验证（全部真实跑通）**
- Run A：盘上 language=en → 启动英文 → 点顶栏胶囊 → DOM 变中文（`上传队列|历史记录1|本地目录|云端目录 // 简体中文`）
  → 切云端目录仍中文 → 磁盘 `config.language = zh`，html lang=zh-CN。
- Run B：盘上 language=zh → **启动直接中文**（持久化读取 OK）→ 设置面板显示 `English|简体中文*`
  → 点 English 段 → 立即切回英文 + 磁盘 `language = en` + 配置文件注释头重新生成为英文。
- 临时验证代码已删除；`npm run typecheck` + `npm run build` + 干净启动冒烟均通过。

**新增文档**：`README.zh-CN.md`、`build/README.zh-CN.md`（英文版为默认，两份顶部互链）。
默认英文那份刻意保留 3 行中文（语言链接 / 语言名 / 界面语言名），属预期。
